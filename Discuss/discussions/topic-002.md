# 議題

## テーマ
PMが社内業務でどのように GitHub Copilot を使えるか

## 背景・前提条件
- PMは見積、WBS、進捗管理、課題管理、会議運営、レビューなどの社内業務を広く担当している
- GitHub Copilot の利用環境として VS Code と Copilot CLI を想定する
- 対象は実装そのものより、社内向けの文書作成、情報整理、レビュー支援、たたき台作成、運用改善とする
- PM自身は毎日コードを書くとは限らず、開発者以外にも横展開できるかを見極めたい
- 機密情報、個人情報、顧客固有情報の扱いには注意が必要で、誤情報の混入や過信は避けたい
- 成果物はこのリポジトリのフォルダ構成に沿って管理する前提とする

## ゴール
PMが VS Code や CLI を使って何を効率化できるかを具体化し、すぐ試すべき使い方と避けるべき使い方を整理する

## 検討観点
- VS Code で相性がよい PM 業務は何か
- CLI で相性がよい PM 業務は何か
- 議事録、課題整理、WBS 作成、進捗報告、設計レビュー、テスト観点出しでどう使えるか
- 下書き生成、要約、差分確認、論点整理、レビュー支援のどこに最も効果があるか
- 人が最終判断すべき工程と、Copilot にたたき台を任せてよい工程の線引きはどうするか
- プロンプトやテンプレートをどう蓄積し、再利用可能な運用にするか
- セキュリティ、監査、説明責任の観点で最低限必要なルールは何か
- 導入効果をどう測るか。時間短縮、品質向上、属人化低減の観点で評価できるか
- PM本人が見落としがちなリスクや、逆に過小評価しがちなメリットがないか
