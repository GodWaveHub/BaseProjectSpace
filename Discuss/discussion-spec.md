# エージェント議論シェル 仕様書

**作成日**: 2026-04-11  
**更新日**: 2026-04-12  
**バージョン**: v1.1

---

## 1. 概要

複数のエージェント（AI）が、指定された議題について役割に基づいた議論を行うPowerShellスクリプト。  
シェルがオーケストレーターとして各エージェントの呼び出し順序を制御し、指定回数の発言が完了するまで議論を繰り返す。

---

## 2. 入出力ファイル構成

```
Discuss/
  ├── discussion-spec.md          # 本仕様書
  ├── discuss.ps1                 # オーケストレーターシェル
  ├── discuss.prompt.md           # エージェント呼び出し用プロンプトテンプレート
  │
  └── discussions/                # 議論データ（議題ごとにサブフォルダ or IDで管理）
       ├── topic-{id}.md          # 議題ファイル（入力）
       ├── agents-{id}.md         # 参加エージェントリスト（入力）
       └── discussion-{id}.md     # 議論ファイル（入出力・蓄積、要約も末尾に追記）

.github/agents/
  ├── {agent-name}.md             # カスタムエージェント定義（既存）
  └── ...
```

> **配置ルール**: 本機能に関するすべての成果物（仕様書・シェル・プロンプトテンプレート・議論データ）は `Discuss/` フォルダに集約する。

### 2.1 議題ファイル（`topic-{id}.md`）

議論の対象となるテーマ・前提条件・ゴールを記述する。

```markdown
# 議題

## テーマ
〇〇システムのアーキテクチャ選定

## 背景・前提条件
- 既存システムはモノリシック構成
- 年間トランザクション数は約100万件
- 来年度中にクラウド移行予定

## ゴール
マイクロサービス vs モジュラーモノリスの方針を決定する
```

### 2.2 参加エージェントリスト（`agents-{id}.md`）

議論に参加するカスタムエージェントの **name** を1行1件で列挙する。  
name は `.github/agents/{name}.md` に対応するカスタムエージェント名を指定する。  
各エージェントの役割・立場は、対応するエージェント定義ファイル（`.github/agents/{name}.md`）の `description` および本文から取得する。

```markdown
# 参加エージェント

- GroupA.planer
- GroupA.designer
- GroupA.creater
- GroupA.tester
```

> **補足**: 上記の例では `.github/agents/GroupA.planer.md` 〜 `.github/agents/GroupA.tester.md` が参照される。

### 2.2.1 エージェント定義ファイルの構造（参考）

シェルは各エージェント定義ファイルから以下を読み取る。

| 取得項目 | 取得元 | 用途 |
|---------|--------|------|
| エージェント名 | ファイル名（`{name}.md`） | 議論ファイルでの発言者名 |
| description | YAMLフロントマター `description` | 議論ログのヘッダ、コンソールログに使用 |
| 役割・指示 | 本文（`# 概要` 以降） | エージェント呼び出し時のコンテキストに含める |

```yaml
# .github/agents/GroupA.planer.md の例
---
description: '基本設計書を作成するエージェントです'
tools: [vscode, execute, read, edit, search, web, todo]
model: Claude Sonnet 4.6 (copilot)
---

# 概要
基本設計書を作成する。
...
```

### 2.3 議論ファイル（`discussion-{id}.md`）

各エージェントの発言が時系列で追記される。シェル起動時に自動作成（既存なら追記）。

```markdown
# 議論ログ

議題: 〇〇システムのアーキテクチャ選定  
開始日時: 2026-04-11 10:00:00  
参加エージェント: GroupA.planer, GroupA.designer, GroupA.creater, GroupA.tester

---

## ラウンド 1

### 【GroupA.planer】（2026-04-11 10:00:15）
マイクロサービスは魅力的だが、現チームの規模を考えるとリスクが高い。
モジュラーモノリスで段階的に分離する方が現実的ではないか。

### 【GroupA.designer】（2026-04-11 10:00:32）
GroupA.planerの意見に一部同意する。ただし、モジュラーモノリスでも…
```

## 3. コマンド仕様

### 3.1 スクリプト配置先

```
Discuss/discuss.ps1
```

### 3.2 引数

| パラメータ | 型 | 必須 | デフォルト | 説明 |
|-----------|-----|------|-----------|------|
| `-TopicFile` | string | ○ | — | 議題ファイルのパス |
| `-AgentsFile` | string | ○ | — | 参加エージェントリストファイルのパス |
| `-Rounds` | int | ○ | — | 議論ラウンド数（全エージェントが1回ずつ発言=1ラウンド） |
| `-DiscussionFile` | string | × | 自動生成 | 議論ファイルのパス。省略時は `Discuss/discussions/` に生成 |
| `-Model` | string | × | `gpt-5.4` | Copilot CLI で使用するAIモデル名 |
| `-Summarize` | switch | × | $false | 最終ラウンド後に要約を議論ファイル末尾に追記する |
| `-Force` | switch | × | $false | 既存の議論ファイルを警告なく上書きする |

### 3.3 実行例

```powershell
.\Discuss\discuss.ps1 `
  -TopicFile "Discuss/discussions/topic-001.md" `
  -AgentsFile "Discuss/discussions/agents-001.md" `
  -Rounds 3 `
  -Summarize
```

## 5. オーケストレーター（発言順序制御）の仕様

### 5.1 基本方針

シェルスクリプト自体がオーケストレーターとして、次にどのエージェントを呼ぶか判断する。

### 5.2 順序決定ロジック

| モード | 説明 |
|--------|------|
| **ラウンドロビン**（デフォルト） | エージェント定義ファイルの記載順に全員が1回ずつ発言して1ラウンド |
| **コンテキスト応答型**（将来拡張） | 直前の発言内容をAIが分析し、最も反論・補足すべきエージェントを選定 |

### 5.3 1ラウンドの定義

- 全エージェントが1回ずつ発言を完了した時点で1ラウンド終了
- `-Rounds 3` の場合、エージェント4名 × 3ラウンド = **合計12回の発言**

## 6. エージェント呼び出し仕様

### 6.1 呼び出し方式

GitHub Copilot CLI (`copilot` コマンド) を利用してエージェントを呼び出す。  
各エージェントには以下の情報をプロンプトとして渡す。

```powershell
copilot -p @"
{プロンプトテンプレートに各値を埋め込んだ内容}
"@ `
  --agent {エージェント名} `
  --allow-all `
  --model "{Modelパラメータの値}"
```

> **ポイント**: `--agent` には `.agent.md` 拡張子なしのエージェント名を指定する。

### 6.2 エージェントへ渡すプロンプト

シェルは以下のテンプレートにファイル内容を埋め込み、エージェントへの単一プロンプトとして渡す。

```
あなたは「{エージェント名}」です。

## あなたの役割
{.github/agents/{name}.md の本文（YAMLフロントマター以降）}

## 今回の議題
以下の議題について議論しています。議題の背景・前提条件・ゴールをよく理解してください。

{議題ファイルの内容}

## これまでの議論（ラウンド {現在のラウンド}/{全ラウンド数}）
以下はこれまでの参加者の発言です。全員の意見を把握したうえで発言してください。
（初回の場合:「まだ誰も発言していません。最初の発言者としてあなたの見解を述べてください。」）

{議論ファイルの現在の内容}

## あなたがやるべきこと
あなたは上記の議題に対して、自分の専門性と役割の観点から **意見を1件** 述べてください。

### 必須事項
1. **議題に対する自分の立場**（賛成/反対/条件付き賛成 など）を明確にする
2. **根拠**を示す（技術的理由、コスト観点、品質観点など、あなたの役割に沿ったもの）
3. **他の参加者への言及**：既に発言がある場合、少なくとも1名の意見に対してコメント（賛同・反論・補足・質問）する

### 禁止事項
- 発言の冒頭に自分の名前を書かないでください（シェルが自動付与します）
- 議題と無関係な話題に脱線しないでください
- 他の参加者の発言をそのまま繰り返さないでください

### 出力形式
- 意見本文のみをテキストで返してください（Markdownヘッダ不要）
- 200〜400文字程度で簡潔にまとめてください
```

### 6.3 エージェントの返却値

エージェントは**意見本文のみ**をテキストで返す。  
シェルが以下のフォーマットで議論ファイルに追記する。

```markdown
### 【{名前}】（{タイムスタンプ}）
{エージェントの返却テキスト}

```

## 7. 要約機能（`-Summarize`）

最終ラウンド完了後、別途サマリエージェントを呼び出し、議論全体を要約する。

### 7.1 要約エージェントへ渡すコンテキスト

```
以下の議論ログを読み、要約してください。

## 出力形式
1. 議論の結論（合意点）
2. 未解決の論点
3. 各参加者の主要な主張（箇条書き）
4. 推奨アクション

## 議論ログ
{議論ファイルの全内容}
```

### 7.2 出力先

議論ファイル（`discussion-{id}.md`）の末尾に `## 要約・結論` セクションとして追記する。

## 8. エラーハンドリング

| ケース | 振る舞い |
|--------|---------|
| 議題ファイルが存在しない | エラーメッセージを表示して終了（exit 1） |
| 参加エージェントリストファイルが存在しない | エラーメッセージを表示して終了（exit 1） |
| リストに記載されたエージェントが0件 | エラーメッセージを表示して終了（exit 1） |
| `.github/agents/{name}.md` が見つからない | 該当エージェント名を表示してエラー終了（exit 1） |
| ラウンド数が0以下 | エラーメッセージを表示して終了（exit 1） |
| エージェント呼び出し失敗 | 最大2回リトライ。それでも失敗時はスキップしてログに記録 |
| 議論ファイルへの書き込み失敗 | エラーメッセージを表示して終了（exit 1） |

## 10. 将来拡張案

| 拡張項目 | 概要 |
|---------|------|
| コンテキスト応答型順序制御 | AIが議論の流れを見て次の発言者を動的に決定 |
| 終了条件の自動判定 | 合意形成された場合にラウンド途中で終了 |
| 投票機能 | 最終ラウンド後にエージェント投票で結論を決定 |
| ファシリテーターエージェント | 議論が脱線した場合に軌道修正する専用エージェント |
| 外部ナレッジ参照 | エージェントが議論中に設計書やドキュメントを参照 |
