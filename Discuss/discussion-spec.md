# subagent 合議 仕様書

**作成日**: 2026-04-11  
**更新日**: 2026-05-17  
**バージョン**: v3.0

---

## 1. 概要

複数の custom subagents に同じ議題を渡し、**メインエージェントがファシリテーターとして議論を収束に導く** 合議方式。  
最大7ラウンドで議論を進め、収束したらその時点で結論を生成する。

> **方針**: ラウンド1は独立意見の収集。ラウンド2以降はメインエージェントが「合意点・未解決論点・次の焦点」をまとめてから次ラウンドを開始。収束判定で早期終了も可能。

---

## 2. 構成

```
Discuss\
  ├── discussion-spec.md             # 本仕様書
  └── discussions\
       ├── topic-{id}.md             # 議題ファイル
       ├── agents-{id}.md            # 参加エージェント一覧
       ├── discussed-{id}.md         # 各エージェントの意見ログ
       └── conclusion-{id}.md        # 最終結論

.github\
  ├── agents\                        # custom agents
  └── skills\
       └── discuss-subagents\SKILL.md
```

---

## 3. 入出力

### 3.1 議題ファイル

従来どおり `topic-{id}.md` を使う。  
記載項目は少なくとも以下を含める。

```markdown
# 議題

## テーマ
〇〇

## 背景・前提条件
- ...

## ゴール
...
```

### 3.2 参加エージェントファイル

必須。skill 側に固定の既定メンバーは持たず、必ずファイルから読む。

ファイル形式は従来どおり箇条書き。

```markdown
# 参加エージェント

- discuss.optimist
- discuss.cautious
- discuss.humor
- discuss.philosopher
```

### 3.3 出力ファイル

出力は 2 ファイルに分ける。

1. `discussed-{id}.md`
   - 全ラウンドの発言ログ（ラウンドごとのセクション＋ファシリテーションメモ）
2. `conclusion-{id}.md`
   - 合意点、対立点、未解決事項、推奨アクションを残す最終結論

議題ファイル名が `topic-{id}.md` なら、上記の `{id}` を使って既定ファイル名を決める。

---

## 4. 実行方式

### 4.1 既定フロー

1. 議題を読む
2. 参加エージェント一覧を読む
3. **ラウンド1**: 全エージェントに議題のみを渡して独立意見を収集する
4. `discussed-{id}.md` の「ラウンド1」セクションに記録する
5. **収束判定**（メインエージェントが実施）→ 収束していればステップ9へ
6. **ファシリテーションメモ作成**: 合意点の要約・未解決論点・次ラウンドの焦点を整理する
7. **ラウンドN（N=2〜7）**: ファシリテーションメモ＋全過去発言を渡して次ラウンドを実施する
8. ステップ5に戻る（最大7ラウンドで強制終了）
9. メインエージェントが全ラウンドを統合して最終結論を生成する
10. `conclusion-{id}.md` に保存する

### 4.2 ラウンド数

- **最大7ラウンド**（ラウンド1〜7）
- 収束判定が真になった時点で早期終了する
- ラウンド1: 全エージェントが独立して意見を述べる（他者の意見は見えない）
- ラウンド2以降: ファシリテーションメモ＋全過去発言を見て議論を深める
- 7ラウンド到達後も未収束の場合は残存対立点を結論の「未解決事項」に明記して終了する

**収束判定基準（いずれかが真なら収束）:**
- 全員の発言に共通する結論または推奨アクションが現れている
- 対立していた論点が「条件付き合意」または「トレードオフの明示」で整理されている
- ラウンドをまたいで新しい論点が出ていない（議論が停滞している）

### 4.3 オーケストレーション

PowerShell やバッチではなく、**skill から subagent を呼ぶだけ** の構成にする。  
発言順は `agents-{id}.md` の記載順を尊重する。  
各ラウンドは逐次実行（前ラウンド全員完了 → 収束判定 → 次ラウンド）。

## 5. subagent への依頼内容

### ラウンド1（初期意見）

各 subagent には議題のみを渡す。他者の意見は見せない。

要求する出力:

- 日本語、150〜400文字
- 1件の意見に絞る
- そのエージェントらしい視点を明確に出す
- 具体的な懸念、判断軸、または次の一手を含める
- メタコメントや定型フッターを書かない

### ラウンド2以降（意見交換・深化）

各 subagent に以下を渡す。

- 議題（再掲）
- 全過去ラウンドの発言（ラウンドごとにセクション分け）
- ファシリテーターのメモ（合意点要約・未解決論点・次ラウンドの焦点）

要求する出力:

- 日本語、150〜500文字
- ファシリテーターが示した「次ラウンドの焦点」に応答する
- 他のエージェントに名前で話しかけてよい
- 弱点を突く / 反例を示す / 鋭い問いを投げる / 主張を発展させる / 妥協点を提案する のいずれかを必ず行う
- 単純な賛同のみで終わらせない
- 友人同士のリアルな会話スタイル
- メタコメントや定型フッターを書かない

## 6. 出力形式

```markdown
# 議論ログ

- 議題: 〇〇
- 方式: subagents（最大7ラウンド・ファシリテーション付き）
- 参加エージェント: discuss.optimist, discuss.cautious, discuss.humor, discuss.philosopher
- 実施ラウンド数: N

## ラウンド1: 初期意見

### discuss.optimist
...

### discuss.cautious
...

## ラウンド2（ファシリテーション後）

> **ファシリテーターの整理:**
> - 合意点: ...
> - 未解決論点: ...
> - 次ラウンドの焦点: ...

### discuss.optimist
...

### discuss.cautious
...
```

```markdown
# 結論

- 議題: 〇〇
- 参加エージェント: discuss.optimist, discuss.cautious, discuss.humor, discuss.philosopher
- 実施ラウンド数: N

## 合意点
- ...

## 対立点（解消済み）
- ...

## 未解決事項（対立が残った場合）
- ...

## 推奨アクション
- ...
```

## 7. 旧方式との違い

| 項目 | 旧方式(ps1) | v2.0 | v3.0（現行） |
|------|------------|------|------------|
| 実行主体 | `discuss.ps1` | repo skill + subagents | 同左 |
| 制御 | シェルでラウンド制御 | メインエージェントが制御 | 同左＋収束判定あり |
| 既定ラウンド | 複数ラウンド想定 | 2ラウンド固定 | **最大7ラウンド（収束で早期終了）** |
| ファシリテーション | なし | なし | **メインエージェントが毎ラウンド整理** |
| 収束判定 | なし | なし | **3条件で自動判定** |
| 未収束時 | — | — | **未解決事項を結論に明記** |
| 入力 | 引数中心 | `topic` / `agents` ファイル | 同左 |
| 出力 | 発言ログ1ファイル | `discussed`＋`conclusion` | 同左＋ラウンド数・ファシリテーションメモ付き |

## 8. 互換・運用メモ

- 今後の標準運用は `.github\skills\discuss-subagents\SKILL.md` を使う。
- まずは `discuss.*` 系エージェントを対象にし、必要になれば他の custom agents に広げる。
- エージェント一覧、議題、結論はすべて `Discuss\discussions\` 配下のファイルで扱う。
