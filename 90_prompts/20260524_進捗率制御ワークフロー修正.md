# 2026-05-24 進捗率制御ワークフロー修正指示

## 実行日時
2026-05-24

## 実行AIモデル
GitHub Copilot (GPT-4o)

## プロンプト内容
「進捗率制御.ymlでは「進捗率[%]」をbodyから探していますが、「進捗率[%]」が、Issueの本文内ではなく、右側のサイドバーにあるGitHub Projects のCustom fieldsとして追加したものです。そもそも issue.body（本文）のテキストデータ内には保存されていません。取得方法の再検討をお願いします。そして修正してください。」

## 問題点
- 旧ワークフローは `issue.body` (本文テキスト) の正規表現で `進捗率[%]: 数値` を探していた
- GitHub Projects の Custom Field はテキスト本文には保存されず、GraphQL API で取得・更新が必要
- `issues` イベントは Custom Field の変更を検知できない

## 修正内容

### トリガー変更
| 変更前 | 変更後 |
|---|---|
| `on: issues (opened, edited, ...)` | `on: projects_v2_item (created, edited)` |

Projects V2 アイテムの作成・編集イベントを使用することで Custom Field の変更を正しく検知する。

### 進捗率の取得・更新方法変更
| 変更前 | 変更後 |
|---|---|
| `issue.body` の正規表現マッチ | GitHub GraphQL API `ProjectV2ItemFieldNumberValue` |
| `github.rest.issues.update({ body })` | `updateProjectV2ItemFieldValue` mutation |

### 必要なシークレット
- `PAT_TOKEN`: `project` スコープを持つ Personal Access Token が必要  
  (GITHUB_TOKEN は Projects V2 への書き込み権限を持たないため)

### フロー概要
1. **initialize-progress** (created): アイテムがプロジェクトに追加されたとき、`進捗率[%]` が未設定なら 0 で初期化
2. **update-parent-progress** (edited): `進捗率[%]` フィールドが変更されたとき、親 Issue の進捗率を子の平均値で再帰的に更新

## 参照ファイル
